Streamer.bot Wiring

The card now computes XP itself from the rates above, so your Streamer.bot actions only need to broadcast the raw event via CPH.WebsocketBroadcastJson() under a Custom event: {eventName, user, avatar, quantity} — where eventName is one of Sub / ReSub / GiftSub / Cheer / Donation / Raid / ChannelPointRedeem, and quantity is bits cheered, subs gifted, raiders, or dollars (omit/1 for flat events like Sub or Channel Point Redeem).

If an action ever broadcasts a fully pre-computed payload instead (xpGained/totalXp/etc. already set, like your old system), the card detects that and uses it as-is — so nothing breaks if you haven't updated your actions yet.

For real grants to persist across Streamer.bot restarts too, add a small action LVL_GrantXP that reads user/eventName/quantity via CPH.TryGetArg, stores running totals in a global var like lvl_xp_{user} (guard first read with a GetGlobalVar null-check), then re-broadcasts the raw event. This mirrors your sw_inv_ / wheel_inv_ pattern.
