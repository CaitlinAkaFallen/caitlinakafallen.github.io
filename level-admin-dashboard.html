Chat Commands

Viewers type these directly in chat; replies post automatically once the bot is connected. Rewards now move through three stages: unlocked → claimed → redeemed.

$claim / $redeem / $wallet / $refund

Chat commands enabled
Master switch for all commands below.
$claim
Step 1 — reserves a named unlocked reward (or the oldest unclaimed one if no name is given). Doesn't mark it as used yet.
$redeem
Step 2 — marks a reserved reward as actually used on stream. If the viewer skipped $claim, $redeem reserves it for them automatically first.
$wallet
Lets a viewer check their own claimed-but-not-yet-redeemed rewards — what they currently have to spend.
$refund {username}
Mod/broadcaster-only. Undoes that viewer's most recent $redeem only — the reward goes back to claimed/reserved. Does not undo a $claim.

Reply Messages

Placeholders: {user} {level} {reward} {badge} {broadcaster} — {items} is available for the $wallet message only.
$claim <reward name> reserves that specific unlocked reward (case-insensitive title match) — e.g. $claim No Swearing. Leave the name off and $claim alone reserves the oldest unlocked-but-unclaimed reward instead.

$redeem <reward name> marks a reward as actually used on stream. It works on anything reserved via $claim, and will auto-reserve on the fly if the viewer calls $redeem directly without claiming first. Leave the name off to redeem the oldest claimed-but-unredeemed reward (or the oldest unclaimed one if nothing's been claimed yet).

$wallet (no argument, viewer's own) lists whatever that viewer currently has claimed but hasn't redeemed yet — their spendable inventory.

$refund {username} (mods/broadcaster only) undoes that viewer's most recently redeemed reward only — it goes back to claimed/reserved, ready to $redeem again. It never touches a plain $claim. Example: $refund fallenoneart.

{broadcaster} fills in with the Stream Account Name saved on the Connection tab, so a message can say things like "redeemed for {broadcaster}'s stream" without hardcoding your channel name.

Setup

Streamer.bot wiring reference for the parts this dashboard can't configure itself.

Streamer.bot Wiring (XP events)

The card computes XP itself from the rates on the Levels & Rewards tab, so your Streamer.bot actions only need to broadcast the raw event via CPH.WebsocketBroadcastJson() under a Custom event: {source:"levelup", eventName, user, avatar, quantity} — where eventName is one of Sub / ReSub / GiftSub / Cheer / Donation / Raid / ChannelPointRedeem, and quantity is bits cheered, subs gifted, raiders, or dollars (omit/1 for flat events like Sub or Channel Point Redeem). The source:"levelup" field is required — both this dashboard and the card overlay only listen for that tag, so unrelated Streamer.bot broadcasts (like other custom actions) are never mistaken for a level event.

If an action ever broadcasts a fully pre-computed payload instead (xpGained/totalXp/etc. already set), the card detects that and uses it as-is — just keep the source:"levelup" tag on it too.

For real grants to persist across Streamer.bot restarts too, add a small action LVL_GrantXP that reads user/eventName/quantity via CPH.TryGetArg, stores running totals in a global var like lvl_xp_{user} (guard first read with a GetGlobalVar null-check), then re-broadcasts the raw event. This mirrors your sw_inv_ / wheel_inv_ pattern.

Chat Commands ($claim / $redeem / $wallet / $refund)

These no longer go through Streamer.bot. Connect your bot account's Twitch IRC credentials on the Connection tab, and this dashboard listens for $claim/$redeem/$wallet/$refund and posts the reply itself. Keep this tab open on your streaming PC so it stays connected during stream.

Rewards move through three stages per viewer: unlocked (level reached) → claimed (reserved via $claim) → redeemed (marked used via $redeem). $redeem will auto-claim on the fly if a viewer calls it without claiming first, so it always works as a one-step shortcut too. $wallet just reads a viewer's own claimed-but-unredeemed levels back to them — it never changes any state.

$refund {username} is restricted to the broadcaster and moderators — the bot reads the sender's IRC badges tag (requires the twitch.tv/tags capability, already requested on connect) to check for broadcaster or moderator before allowing it. It only reverses the most recent redeem (back to claimed) — it never touches a $claim by itself.
